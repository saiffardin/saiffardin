# How this profile is built

Every visual in the README is an animated SVG generated by plain Node.js (no dependencies).
GitHub renders README images through `<img>`, which allows CSS and SMIL animation but no scripts,
so everything here is drawn and animated in SVG alone. Each image exists in a light and a dark
version, and `<picture>` picks the one matching the viewer's GitHub theme.

```
data/profile.mjs        all the content: text, projects, timeline, toolbox, links
scripts/build.mjs       generates /assets/*.svg and README.md
scripts/visuals/*.mjs   one renderer per section
scripts/preview.mjs     local preview pages in .preview/ (GitHub-like, both themes)
.github/workflows/      daily rebuild of the live "pulse" section
```

## Edit and rebuild

```bash
npm run build          # everything (fetches your GitHub activity for the pulse)
npm run build:static   # skip the network: only hand-designed visuals + README
npm run preview        # then open .preview/dark.html or .preview/light.html
```

Change text in `data/profile.mjs` and rebuild. Don't edit README.md by hand: it is regenerated.

## The live section

`.github/workflows/profile.yml` runs every day (and on every push that touches `data/` or
`scripts/`), rebuilds the SVGs, and commits them if anything changed.

By default it only sees public data. To also count private repositories in the language bar,
create a fine-grained personal access token with read-only access to all your repositories
and add it as a repository secret named `PROFILE_TOKEN`.
